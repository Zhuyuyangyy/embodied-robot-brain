## 专利四：基于主动推理与自由能原理的多智能体研究助手系统

### 1. 专利基本信息

**专利名称**：一种基于主动推理自由能原理的_epistemic autonomy_多智能体研究助手系统

**技术领域**：人工智能、多智能体系统、自然语言处理、科学研究自动化

**关联项目**：Embodied-Robot-Brain - 多智能体具身机器人研究助手

---

### 2. 背景技术

#### 2.1 现有技术缺陷

现有多智能体研究助手系统（AutoGen、CrewAI、LangChain Agent、ReAct+知识图谱）遵循经典规划范式，存在根本性局限：

| 现有系统 | 核心方法 | 根本缺陷 |
|---------|---------|---------|
| AutoGen/CrewAI | 多Agent角色扮演+消息传递 | Agent无内部信念模型；惊讶无处安放 |
| LangChain Agent | ReAct循环+工具调用 | 好奇感是外部奖励工程的产物，非内在驱动 |
| ReAct+KG | 知识图谱存储事实 | KG是静态的；惊讶时只添加事实，不改信念结构 |
| Curiosity-RL | 信息增益奖励 | 须人工设计奖励函数；无法区分"惊讶"和"噪声" |

**现有技术共性缺陷**：

1. **Agent不知道"自己不知道什么"** — 贝叶斯信念更新只传播已知信息，不建模自身无知。Agent对自己模型的 misspecification 完全盲目
2. **探索是外部驱动的，不是内在的** — 所谓"好奇心"须人工添加为奖励项，须为每个领域重新设计，无法跨领域泛化
3. **失败是错误，不是信息** — 当执行结果与预期不符时，系统视为需要修复的"错误"，而非揭示模型缺口的"信息"
4. **多Agent知识图谱是静态的** — 惊讶触发"添加新事实"但不触发"修改图谱结构"，导致知识图谱随时间膨胀但质量不提升

### 3. 发明内容

#### 3.1 核心创新点概述

本发明提出 **Active Inference Agent（主动推理智能体）**架构，将研究助手从"规划执行器"重定义为"惊讶最小化器"：

- Agent目标不是"完成任务"而是"最小化关于世界的自由能"
- 好奇心是内在驱动力——不是添加的奖励项，而是最小化自由能的数学必然
- 惊讶触发模型修正，而不仅是添加新事实
- 多Agent共享**认知态图谱（Epistemic State Graph）**，每条边附带置信度和被挑战历史

#### 3.2 创新点一：自由能最小化框架

**技术方案**：

每个Agent维护一个生成模型 P(o, z) = P(o|z, θ)·P(z|ψ)，定义自由能：

```
F(o) = -log P(o) + KL[q(z|o) || P(z|o)]
```

Agent选择行动来最小化期望未来自由能 G(a) = E[F(o')]：

```python
class FreeEnergyAgent:
    """
    基于自由能原理的主动推理Agent。
    核心目标不是完成任务，而是最小化对世界的自由能。
    好奇是内在驱动力——这是数学必然，不是工程技巧。
    """
    
    def __init__(self, generative_model, prior_preferences):
        self.GM = generative_model  # P(o|z,θ) · P(z|ψ)
        self.prior_preferences = prior_preferences  # 偏好观测分布
        self.surprise_threshold = 2.0  # 触发模型修正的惊讶阈值
    
    def select_action(self, observation_history):
        """
        选择最小化期望自由能的动作。
        G(a) = E_{q(o'|do(a))}[F(o')] = 务实价值 + 认知价值
        """
        candidate_actions = self.get_candidate_actions()
        expected_free_energies = []
        
        for a in candidate_actions:
            # 模拟执行动作a后的观测分布
            simulated_obs_dist = self.simulate_action(a, observation_history)
            # 计算期望自由能
            g_a = sum(
                self.free_energy(o) * p 
                for o, p in simulated_obs_dist.items()
            )
            expected_free_energies.append((a, g_a))
        
        # 选择最小化期望自由能的动作
        best_action = min(expected_free_energies, key=lambda x: x[1])[0]
        return best_action
    
    def free_energy(self, observation):
        """
        计算观测o的自由能。
        F(o) = -log P(o) + KL[q(z|o)||P(z|o)]
             = -log P(o) + 数据拟合误差 + 复杂度代价
        """
        # 第一项：观测在当前模型下的对数似然（"惊讶度"）
        surprise = -self.GM.log_prob_observation(observation)
        
        # 第二项：变分后验与先验的KL散度（模型复杂度代价）
        posterior = self.GM.infer_posterior(observation)
        model_complexity = self.GM.kl_divergence(posterior)
        
        return surprise + model_complexity
    
    def expected_free_energy(self, action):
        """
        计算动作a的期望自由能 G(a)。
        G(a) = E_{q(o'|do(a))}[F(o')]
        
        分解为两部分：
        G(a) = 务实价值(Pragmatic Value) + 认知价值(Epistemic Value)
        
        务实价值：当前模型下，a能否带来好结果（偏好实现）
        认知价值：执行a后，模型对世界的了解会增加多少（减少不确定性）
        
        认知价值 = 最大化的信息获取——这就是"好奇心"的数学定义！
        """
        # 务实价值：在当前模型下，a实现偏好观测的程度
        pragmatic = self._compute_pragmatic_value(action)
        
        # 认知价值：执行a后期望减少的信念不确定性
        epistemic = self._compute_epistemic_value(action)
        
        return pragmatic + epistemic
    
    def _compute_epistemic_value(self, action):
        """
        认知价值 = 执行动作a后期望的信息增益。
        
        这是本发明的核心创新：
        "好奇"不是人工添加的奖励项，
        而是自由能最小化框架的数学必然推论——
        因为减少关于世界的无知会直接降低期望自由能。
        
        具体计算：互信息 I(z; o | do(a))
        = H[z] - H[z | do(a)]
        = 在知道a的结果之前和之后，隐状态的不确定性差异
        = 执行a能减少多少关于隐状态的未知
        """
        # 候选观测下的隐状态后验
        posteriors = self.GM.get_posteriors_after_action(action)
        current_entropy = self.GM.current_state_entropy()
        
        # 执行a后的期望熵
        expected_entropy = sum(
            self.GM.state_entropy(p) * prob 
            for p, prob in posteriors.items()
        )
        
        # 互信息 = 执行a减少的不确定性
        epistemic_value = current_entropy - expected_entropy
        return epistemic_value
```

#### 3.3 创新点二：惊讶检测与主动模型修正

**技术方案**：

当观测到的自由能超过阈值时，触发主动模型修正——不只是更新参数，还要更新模型结构：

```python
class SurpriseDrivenModelRevision:
    """
    惊讶驱动的主动模型修正。
    关键洞察：失败不是错误，而是信息。
    失败揭示了模型与现实之间的差距——修正这个差距就是学习。
    """
    
    def __init__(self, generative_model, epistemic_state_graph):
        self.GM = generative_model
        self.ESG = epistemic_state_graph
    
    def on_observation(self, observation):
        """每次观测后检查是否触发模型修正"""
        F = self.free_energy(observation)
        
        if F > self.surprise_threshold:
            self._trigger_model_revision(observation, F)
    
    def _trigger_model_revision(self, observation, surprise_level):
        """
        触发主动模型修正流程：
        1. 识别哪些信念被该观测挑战
        2. 找到能解释该观测的最小模型修正
        3. 将修正传播到ESG相关节点
        """
        # 步骤1：找到被挑战的信念
        challenged_beliefs = self._identify_challenged_beliefs(observation)
        
        # 步骤2：生成候选修正
        candidate_revisions = self._generate_revision_hypotheses(
            observation, challenged_beliefs
        )
        
        # 步骤3：选择最简修正（奥卡姆剃刀：选能解释观测的最简单修正）
        best_revision = self._select_minimal_revision(candidate_revisions)
        
        # 步骤4：执行修正，更新GM参数
        self.GM.apply_revision(best_revision)
        
        # 步骤5：传播到ESG
        self.ESG.propagate_challenge(challenged_beliefs, surprise_level)
        
        # 步骤6：记录修正历史（用于审计和解释）
        self._log_revision_event(observation, challenged_beliefs, best_revision)
    
    def _identify_challenged_beliefs(self, observation):
        """
        识别哪些现有信念被当前观测所挑战。
        方法：计算每个信念在当前观测下的"预期一致性"。
        低于阈值的信念 = 被挑战。
        """
        challenged = []
        for node_id, node in self.ESG.nodes.items():
            for edge_id, edge in self.ESG.edges.items():
                # 计算该边（关系）在当前观测下的预期一致性
                expected_consistency = self.GM.predict_edge_consistency(
                    edge_id, observation
                )
                if expected_consistency < 0.5:  # 阈值
                    challenged.append((node_id, edge_id, expected_consistency))
        return challenged
    
    def _generate_revision_hypotheses(self, observation, challenged_beliefs):
        """
        生成能解释该观测的候选模型修正集合。
        修正类型：
        1. 参数修正：调整现有关系的强度
        2. 结构修正：添加/删除关系
        3. 先验修正：调整先验分布的参数
        """
        hypotheses = []
        
        # 类型1：微调被挑战关系的强度
        for (node_id, edge_id, consistency) in challenged_beliefs:
            # 降低该关系的置信度
            new_strength = self.ESG.edges[edge_id]["confidence"] * consistency
            hypotheses.append({
                "type": "parameter",
                "edge_id": edge_id,
                "change": ("scale", new_strength),
                "parsimony_score": 1.0  # 最小修正，parsimony最高
            })
        
        # 类型2：引入新的隐变量解释观测
        hypotheses.append({
            "type": "structural", 
            "action": "add_latent_variable",
            "new_var_properties": self._infer_latent_from_observation(observation),
            "parsimony_score": 0.5  # 结构修正代价更高
        })
        
        # 类型3：添加新关系连接被挑战节点与观测
        hypotheses.append({
            "type": "structural",
            "action": "add_edge",
            "source": challenged_beliefs[0][0] if challenged_beliefs else None,
            "target": "observation_node",
            "parsimony_score": 0.7
        })
        
        return hypotheses
```

#### 3.4 创新点三：认知态图谱（Epistemic State Graph, ESG）

**技术方案**：

ESG = 知识图谱 + 认知元数据：

```python
class EpistemicStateGraph:
    """
    认知态图谱：在传统知识图谱基础上增加认知维度。
    每条边有：(source, target, relation, confidence, challenge_history)
    challenge_history: [(observation, surprise_level, revision_triggered), ...]
    
    当某条边被频繁挑战，说明这条边可能是错误的，或适用范围有限。
    """
    
    def __init__(self):
        self.nodes = {}  # node_id -> {"type": ..., "confidence": float, "last_revised": timestamp}
        self.edges = {}  # edge_id -> {"source": ..., "target": ..., "relation": ..., 
                         #           "confidence": float, "challenge_history": []}
        self.epistemic_threshold = 0.3  # 置信度低于此值标记为"危险信念"
    
    def add_belief(self, source, target, relation, initial_confidence=1.0):
        """添加新信念到图谱"""
        edge_id = f"{source}_{relation}_{target}"
        self.edges[edge_id] = {
            "source": source,
            "target": target,
            "relation": relation,
            "confidence": initial_confidence,
            "challenge_history": []
        }
        return edge_id
    
    def propagate_challenge(self, challenged_edges, surprise_level):
        """
        将挑战传播到认知相关的其他边。
        当边A被挑战，与A有共同节点的边B也应该被"怀疑"。
        
        例如：假设"Hypothesis_A predicts Outcome_B"被新观测挑战，
        那么"Hypothesis_A supports Theory_C"这条边也应该被降权，
        因为支持Hypothesis_A的整个信念簇可能都需要重新评估。
        """
        for (node_id, edge_id, consistency) in challenged_edges:
            # 获取该节点的邻边
            adjacent_edges = self._get_adjacent_edges(node_id)
            
            for adj_edge_id in adjacent_edges:
                if adj_edge_id == edge_id:
                    continue
                # 邻边降权：降权幅度与surprise_level成正比
                decay = surprise_level * 0.1
                self.edges[adj_edge_id]["confidence"] *= (1 - decay)
                
                # 如果邻边置信度低于阈值，递归传播
                if self.edges[adj_edge_id]["confidence"] < self.epistemic_threshold:
                    self.propagate_challenge(
                        [(None, adj_edge_id, self.edges[adj_edge_id]["confidence"])],
                        surprise_level * 0.5  # 递减
                    )
    
    def get_epistemic_status(self):
        """
        返回整个图谱的认知状态摘要。
        用于可视化展示：哪些信念被频繁挑战？哪些高度稳定？
        """
        stable = [e for e in self.edges.values() if e["confidence"] > 0.8]
        uncertain = [e for e in self.edges.values() if 0.3 < e["confidence"] <= 0.8]
        challenged = [e for e in self.edges.values() if e["confidence"] <= 0.3]
        
        return {
            "total_beliefs": len(self.edges),
            "stable_count": len(stable),
            "uncertain_count": len(uncertain),
            "challenged_count": len(challenged),
            "most_challenged": sorted(challenged, key=lambda x: len(x["challenge_history"]), reverse=True)[:5],
            "most_stable": sorted(stable, key=lambda x: x["confidence"], reverse=True)[:5]
        }
```

### 4. 具体实施方式

#### 4.1 系统架构

```
观察流（论文数据、实验结果、任务状态）
    ↓
惊讶检测模块 → 计算每条观测的自由能 F(o)
    ↓
  F > 阈值 → 触发主动模型修正
  F ≤ 阈值 → 正常信念更新
    ↓
生成模型更新 + ESG传播
    ↓
期望自由能计算 → 候选动作排序
    ↓
选择动作执行（文献检索/实验设计/任务更新）
    ↓
结果反馈到观察流（循环）
```

#### 4.2 与传统多Agent系统的根本区别

| 维度 | AutoGen/CrewAI | 本发明 |
|------|--------------|-------|
| Agent目标 | 完成任务（任务奖励） | 最小化自由能（认知+务实双重目标） |
| 好奇机制 | 无（或人工奖励） | 内在：认知价值 = G(a)的数学项 |
| 惊讶处理 | 错误处理 | 主动模型修正 |
| KG/KG结构 | 静态：添加新事实 | 动态：修正+传播+降权 |
| 知识质量 | 随添加增加，无退化机制 | 持续评估：被频繁挑战的信念降权 |

### 5. 权利要求书要点

**独立权利要求1**：
一种基于主动推理自由能原理的多智能体研究助手方法，其特征在于：
（a）为每个智能体建立生成模型 P(o|z, θ)·P(z|ψ)，建模该智能体对研究领域的认知；
（b）定义自由能 F(o) = -log P(o) + KL[q(z|o)||P(z|o)]，作为智能体对观测的惊讶度量；
（c）定义动作的期望自由能 G(a) = E_{q(o'|do(a))}[F(o')]，分解为务实价值和认知价值；
（d）智能体选择使 G(a) 最小化的动作；
（e）当观测自由能超过阈值时，触发主动模型修正而非简单的错误处理。

**独立权利要求2**：
一种实现权利要求1所述方法的多智能体系统，包括：自由能计算模块、惊讶检测模块、主动模型修正模块、认知态图谱模块。

**从属权利要求3**：
根据权利要求1所述的方法，其特征在于，所述认知价值通过互信息 I(z; o | do(a)) = H[z] - H[z | do(a)] 计算，即执行动作后隐状态不确定性的减少量。

**从属权利要求4**：
根据权利要求1所述的方法，其特征在于，所述认知态图谱为带认知元数据的知识图谱，其中每条边记录置信度和被挑战历史，当任一边被触发修正时，递归传播到相邻边。

**从属权利要求5**：
根据权利要求1所述的方法，其特征在于，所述主动模型修正包括：识别被观测挑战的信念集合、生成候选修正假设、基于奥卡姆准则选择最简修正、执行修正并传播到认知态图谱。
